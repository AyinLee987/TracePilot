# Timely ML execution review

Three actual Claude CLI reviews used `claude-opus-5-5` (verified in `modelUsage`),
read-only, without budget or turn limits. The third review found no confirmed
blocker; the two pre-payment questions have been checked below. Private raw
review JSON is retained locally and its hash binds activation evidence.

## Findings and disposition

- Terminal accounting and cancellation: fixed. Infrastructure failures are
  censored rather than scored as model errors; interruptions get their own row
  status. Every planned row remains represented, unknown usage retains the
  unspent batch reservation, and cleanup uncertainty preserves study locks.
  `timely_batch.exclusive` explicitly retains a lock on `ProcessCleanupError`.
- Missing calibration and scheduling: fixed. Incomplete calibration is marked
  partial; missing cells are explicit. Repeat precedes multiplier in the frozen
  row order. `protocol_complete` distinguishes finishing the permitted protocol
  from executing all 384 episodes; the CLI still exits nonzero for an incomplete
  matrix. Censored/missing scores are NA, not observed model zeros; a zero-filled
  planned-denominator view, if shown, must be labeled a lower bound.
- Clock service lifetime: fixed. No fixed eight-hour expiry during active use;
  it stops after ten idle minutes. Three bounded read attempts are allowed and
  recorded. Windows host monotonic readings replace only the timer dependency;
  upstream loop/score selection remain unchanged. The original WSL clock source
  was restored after unsuccessful clock-source diagnostics.
- Deadline metadata: confirmed `deadline_s` is only a scalar trace label in
  `timely_transport.py`; it does not enforce a hidden guest-clock cutoff.
- HTTP guard: retained the explicit 60-second, one-attempt policy. Historical
  four-game requests (not ML) had Pro n=6261, p99=4.177 s, max=11.787 s; Flash
  n=6260, p99=5.383 s, max=6.215 s under their recorded guest clock. This does not
  guarantee long ML generations will fit. Any provider failure stops dispatch;
  already dispatched unknown usage is held, never silently retried.
- Upstream integrity: `git status --porcelain -- src` was empty before freezing.
  All upstream Python files are additionally hashed in the ML plan.
- Isolation/export: public-only mounts, bounded regular-file export, container
  labels and final residual scan verified. Docker `cp` could not read the tmpfs
  submission reliably; the final adapter uses an isolated Python reader.
- Environment effects: possible resource-limit failures are tagged, while
  original error feedback is retained. The 2 GiB tmpfs shares the 4 GiB memory
  cgroup. Timing includes synchronous clock reads, grading and trace writes in
  a shared two-worker event loop; cross-episode blocking is possible, and global
  event-loop lag is reported. No per-episode causal attribution is claimed.
- Private labels remain outside the container. Upstream's host subprocess
  exposes whatever whole input directory it is given; this adapter deliberately
  mounts only public data. Authors' unpublished environment/layout is unknown.
- Fixed research configuration remains in this adapter; no new general-purpose
  abstraction, routing layer, pytest suite or framework fork was introduced.

## Validation

Zero-provider E2E used all four real datasets and the original scorer, with
predetermined scikit-learn training code and fake HTTP. All four submissions
were valid and nonperfect. Checks covered concurrent episodes, missing-code
feedback, package imports, blocked network/private-data/credential access,
read-only data, symlink rejection, runtime timeout and cancellation cleanup.

Additional scheduler checks verified unknown-usage stop, two in-flight cancelled
rows recorded as `censored_interrupted`, a CNY 50 synthetic reservation retained,
and explicit missing-calibration rows. No containers remained. These checks
are engineering evidence, not paid model results.

The independent Windows observation of the clock bridge measured 28.1515868 s
versus 28.1516042 s (difference 0.0000174 s). Guest clocks disagreed and remain
diagnostics only. This short validation does not guarantee absence of later
host sleep, clock-service failure or load effects.
