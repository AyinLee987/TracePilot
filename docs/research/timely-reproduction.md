## 3. 官方语义与研究扩展

发布版 interactive 的 `run_speed_eval()` 测每步均值 τ，`run_full_eval()` 使用 `max_steps × τ` 的时间预算，且 `max_steps` 同时限制循环数。各模型相同 step 列表并非相同秒数。

`tool_durations` 只累加到计时值，没有真实 sleep；`Timer(mode="static")` 带约 ±1% 噪声。先执行动作再判停，最终保留环境分数。官方协议复验保留这些行为，额外记录单调墙钟、模型时间和模拟工具时间，不把模拟时间叫实际等待。延迟档通过配置注入，CLI 没有该参数；自选字典须明确披露。

Jericho 4.0 改变未指定 seed 时的行为。首先验证 Linux/WSL、Python 3.12.3、Jericho 3.2.1 环境，记录依赖和默认种子语义，新版本不能静默混入。[官方兼容说明](https://github.com/microsoft/jericho#breaking-changes-in-jericho-40)

R3 才加入共同绝对 deadline 和实际等待。固定环境/反馈生成规则，相同动作与状态产生相同语义反馈，允许策略分叉；共同状态的局部续跑与原生完整运行分开。所有测试速度条件沿用开发阶段冻结的共同绝对时限集合 D（秒），状态与分支继承原任务分组。基线和信息时点以 [文献报告第 7 节](speed-feedback-related-work.md) 为依据。

任务域分开：R1/R2 使用 Jericho 验证官方 evaluator、模型格式和计时行为；R3/R4 首先转到可隔离执行、具有可见检查与隐藏验收的编程任务。反馈修复、已有正确行为退化、盲重采样和共同错误状态均在编程域定义并冻结；不将游戏得分变化直接标为同一类修复。Jericho 后续如保留，只作为独立的交互任务对照，不据此承诺游戏上的同构纠错分析。早期 E1 的固定档案链任务不扩展，与官方 Jericho 游戏不同。

## 4. 第一批资源与费用边界

总预算仍为人民币 2,000 元，用于新增实验 API/租卡支出；此前实验累计峰值价格估算 0.162511296 元，非账单。Claude 使用现有登录/额度并单列使用量，CLI 报价估算不当作实际新增扣费。执行者在总预算内为本次先导划分累计 200 元上限，从本计划后的首条真实请求起算，包含所有开发、失败和重试；不同时启动多个各占 200 元的批次。10 月 5 日夜间批次已结束，原上限不额外结转。

- 环境检查与固定动作游戏检查：0 次模型调用。
- 首个真实短轨迹只运行 `speed_eval`：`deepseek-flash`、单游戏、最多 8 回合、串行；上限 5 元，每请求输出最多 2,048 tokens。该过程本身就是测速，无额外测速请求；外层/SDK 均不重试，实际预期最多 8 次请求，transport 的 12 次为总保护上限，不是自动重试额度。
- 通过后的小矩阵：单游戏、两模型、两档逻辑工具延迟、两个短步数预算、两次重复；测速单独记账但纳入累计上限。放大前冻结具体步数、每模型测速重复数、官方均值 τ 的计算、交错顺序和时间戳，报告 τ 分布，不把一次 API 时延当固有速度。启动须满足保守预留不超过剩余先导上限；不能据此主张通用排序或显著性。
- 不自动充值或租卡。额外 endpoint、未发布资产或余额缺项具体报告，其他可独立推进的工作继续。

服务固定为官方 DeepSeek，key 从现有 Agent 项目 env 文件读取，仅存在进程内，不打印、不写入 trace/Git、不发送到其他 provider。确切请求 model 参数为 `deepseek-flash`、`deepseek-v4-pro`，对应价格页的 DeepSeek-V4.1-Flash 和 DeepSeek-V4-Pro-0813；transport 显式映射已知价格，未知名称拒绝。另记录返回标识，不猜参数量，也不预设谁更快。

[2026-10-06 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)峰值 USD/百万 tokens：Flash 输入未命中 0.30、命中 0.006、输出 1.20；Pro 为 1.32、0.044、3.96。规划固定 8 CNY/USD，非汇率预测。每请求按输入字节、消息开销上界与最大全价输出预留；未知用量保留全额预留并停后续付费请求。实测 usage 估算与未知预留分列，不当账单。

官方 Agent 重试与 SDK 隐式重试影响开销。外围记录实际 requests；首次复验明确单次尝试，并将差异写进 manifest。原始提示、回答、用量留 `.local/`，脱敏统计入库。模型生成代码仅在受限隔离环境执行，普通临时工作目录不算安全沙箱。

## 5. 验证与推进条件

先验证环境、预算拒绝/未知用量及完整调用路径，经 Claude CLI 代码审查后调用付费模型。每阶段记录命令、版本、原始数据位置、完整分母、失败和预算。游戏指标用真实分数/终态，不把官方 `successful_games` 的“有步骤结果”当通关；单列解析失败和工具参数错误，可识别的游戏拒绝动作另标，不能把格式适配问题当作推理能力差异。若修改提示，另开披露适配的实验条件，保留原版结果。

R2 放大前，所有运行必须关联请求与轨迹，未知费用为零或已停批次处理，墙钟和官方逻辑时间可重算。R3/R4 的数据划分、deadline、预测指标、精度目标及停止条件在对应数据生成前冻结，不根据测试胜负挑点。

本计划尚无新的能力结果。完整目标包括后续机制与预测实验，R0 或短轨迹完成时不将整个目标标为完成。
