## 1. 预测对象与信息时点

只做离线预测：用 Flash 在任务就绪后 **5 秒冻结时点可见的前缀**，预测同一任务、policy、tool delay、repeat 配对的两条独立轨迹在 **15 秒**时的差值：

`y = hidden_pass(Flash_selected_at_15s) - hidden_pass(Pro_selected_at_15s)`，取值为 `-1, 0, 1`。

模型 literal ID 为 `deepseek-flash`、`deepseek-v4-pro`。配对沿用预定 repeat 标签，不声称供应商采样 seed 相同。选中候选仍由公开分最高、平分取最早可用决定；隐藏评分只作运行结束后的标签。正常观察到截止时间但无可交付候选时，该模型的 `hidden_pass` 记 0（并非把配对目标 `y` 记为平局）；未启动、提前中断、未评分和 infrastructure 不确定性不能记 0，完整规划分母保留，缺标签数量单列。

5 秒特征必须由时间戳重建，沿用 `available_at_s < 5` 的严格交付规则。可以知道已发起请求、当前在途状态及截至 5 秒的已耗时；不能回填之后才收到的响应、usage、完整请求耗时、公共结果或最终费用。**禁止使用 Pro 的目标任务前缀、结果、速度、缓存和 usage，也禁止任何目标任务隐藏分数或题号标识作为特征。** 开发标签可以来自运行后的评分，但任何特征只来自 Flash 的可见前缀及预先已知条件。

这是对两模型均从任务就绪时开始的独立运行结果作预测。没有实际执行“先探测 Flash 五秒，再让 Pro 接管”，也没有测量交接代价；不能将离线预测准确性写成满足 15 秒预算的在线 router 收益。

## 2. 固定小模型与强基线候选

拟定三档嵌套输入，**使用同一个简单回归器和同一训练流程**，避免用不同模型容量制造特征增益：

| 档位 | 只在 Flash 5 秒前可见的输入 |
| --- | --- |
| 常数 | 仅截距，即训练任务标签的等任务权重均值 |
| 当前公开进度与速度基线 | 已知 policy/delay；是否已有 eligible 候选；当前最好公开通过比例；首轮解析状态；已完成请求数、eligible 数；首个 eligible 时间；已完成 HTTP 的平均耗时；在途标记及已等待时间 |
| 少量轨迹增量 | 在上一档上增加四项：相邻已返回公共结果的分数改善次数、回退次数、重复候选源码 hash 次数、已观察到的解析失败次数 |

无候选、首轮解析尚未知、无已完成 HTTP 等情况显式带缺失标记；不能把缺失填成观测成功或失败。只比较双方公开结果均已可见的相邻轮次。相同候选 hash 仅用作重复行为特征，不合并独立尝试的评分。

回归器候选为带截距的 ridge，固定 `alpha=1`，截距不惩罚；数值标准化、缺失填充值仅用该训练折估计，零方差列固定为 0。预测截断到 `[-1, 1]`，截断规则三档相同，不另调分类阈值。没有网格搜索、文本嵌入或题目难度人工标注。**这些输入和 ridge 只是待审的可执行选择，不是已有科学贡献或已验证最佳基线。** 若字段可用性或契约检查要求修改，应记录原因和新版本，在留出实验前重新冻结，不能根据留出效果修改。

## 3. 开发验证与可辨识性

开发集只用 R3 的八个 native 任务组：55、32、7、56、16、99、18、31。一个任务的两模型、全部 policy/delay/repeat 始终同组，做完整 **leave-one-task-out（LOTO）**。共同错误状态的 16 条轨迹只作描述，不进入预测拟合或独立测试样本。完整八题为主分析，排除 /32 的七题结果为预定判定器敏感性分析，不因分数好坏选择报告版本。

主指标拟定为等任务权重 MAE，另列 MSE、`y=-1/0/1` 支持数和逐题误差。每个留出开发任务的预测由其他任务训练得到；标准化、缺失处理和任何参数都不得跨折。比较增量特征与常数、强公开进度基线的逐任务误差差值，保留三档全部结果。重复、配对行和两个快照不是独立任务；不从少数任务点宣称统计显著性或跨任务域泛化。

进入留出前，核对完整分母、标签观测情况、每个训练折可用任务数以及标签变化。若开发标签无变化，应明确“当前开发数据无法验证相对质量预测”，不启动留出数据来寻找变化、挑模型或挽救结论。若标签变化存在但简单基线已解释全部可见差异，记录未证明轨迹增量价值，不预设必须得到正结果。具体可用样本门槛与继续决定须依据封存开发证据另行写定，不能在看到留出标签后补定。

原生首稿公开/格式失败 stratum 少于三题，只限制该数据对**跨题反馈机制/因果效应**的支持；不自动等同于所有相对质量预测都必须停止。相反，达到三题也不证明机制或预测有效。预测是否可检验取决于其自身标签、任务组和完整观测支持。

## 4. 拟定留出矩阵与评价顺序

保留题 **43、25、156、145**，拟定 `4 tasks × 2 models × 2 policies × delays {0,2}s × 2 repeats = 64` 条物理轨迹，对应 32 个配对目标。policy 仍为 resample/repair；不加入共同 seed 分支。保留相同绝对 **5/15 秒**截止、相同请求参数和公开选择规则；2 秒是新 tool delay 条件，不能为它重新放宽截止时间。重复数、顺序和全部 run ID 在 plan 中预写，按任务/条件交错并反转第二轮顺序，不删行、不因失败补跑。

完成开发 LOTO 与继续决定后，用全部允许开发任务分别拟合三档并冻结特征实现、训练数据引用、系数、预处理和预测文件格式。留出 Flash 前缀产生后，先保存带 hash 的预测文件，再与独立离线隐藏标签连接评分；不使用 Pro 前缀帮助预测。分别报告“新任务、delay 0”和“新任务、新 delay 2”，不在新条件下重新拟合或调阈值。若缺少完整标签，保留 64/32 规划分母及缺失原因，不能将未知配对记作平局。
