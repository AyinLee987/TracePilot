# 从逐轮轨迹到可迁移经验：候选方案

日期：2026-10-07。状态：**设计建议，尚未实现或验证效果**。以[本批证据](timely-iteration-analysis.md)为起点，不修改模型权重；提炼、验证和检索记忆仍有时间/token/费用，training-free 不等于 cost-free。

## 当前推荐的问题

**一条从失败轨迹总结的经验，在什么可观测条件下应被采用，才能在新任务上减少重复错误，并在共同时间上限内保持或提高成功率？**

用户希望“从开始直接跳到答案”。问答中可以复用解题程序，但有状态的 Agent 必须实际建立环境终态。合理目标是跳过可避免的错误和无用往返，保留必要工具操作与验收；不能把旧任务的最终文本当作新任务已经完成，也不能直接照抄成功动作序列。

## 本批可提炼的候选卡片

每张卡固定记录：适用的可见条件、失败现象、证据来源、原因假说、建议步骤、成功检查、不适用条件、版本与验证状态。事实和推测分开。候选生成只能读取训练组轨迹；本批已被我们全面查看的数据只能作开发材料。

| 候选 | 证据与条件 | 建议及验证 | 不应学到什么 |
| --- | --- | --- | --- |
| 单调用协议 | 官方循环每轮只执行首个调用；episode-322 有大量未执行调用 | 当前 harness 明确 single-call 时只输出一个合规调用，等待反馈后续作；检查是否执行及参数是否正确 | 不得对所有 Agent 禁止并行；支持批量调用的环境不适用 |
| 必需参数修复 | episode-216 的 8 次缺失 action 未进入环境 | 根据 schema 和错误消息补齐 action，先验证参数；不要总结新的领域答案 | 不得把缺参错误当环境执行失败后盲目重试 |
| 格式循环恢复 | episode-369 的 100 个响应都未产生有效调用 | 在开发集比较错误后最小格式示例、精确 schema 提醒与原反馈；候选经验证才启用 | 不能从这一例认定换模型或缩短上下文必然有效 |
| 有前提的风险检查 | episode-129 第 32 轮出现 40→30 | 将高风险动作的前置条件与退出/失败信号列作待查；需要状态恢复后的对照或新任务验证 | 不能直接写成“不要攻击 troll”这类答案记忆 |
| 进展检查 | 重复反馈与后续加分共存，如 episode-365 | 结合已完成子目标、可见状态及后续 verifier，验证是否陷入重复；阈值只在开发集选 | 不能把零即时奖励、重复文本全部当负样本 |

前两项更像必要工程基线，不宜作为论文主要创新。第一版应先做小型版本化卡片集合和简单检索，不生成通用工具/自修改代码框架，也不同时训练 router。

## 有针对性的学习流程

1. **收集失败段与对照成功段。** 以一次错误/子目标为单位，保留触发前的可见信息、动作、反馈和后续客观结果。格式修复与任务推进分别标记。
2. **生成条件化程序。** 将实体名、答案、固定路径替换成任务槽位；写清“何时使用、怎么检查、何时停止/拒绝”。无法证实原因的卡片保持 hypothesis 状态。
3. **在开发任务上验证并决定接纳。** 比较旧版本与候选版本的完整任务结果；包含适用样本、表面相似但不适用样本、原本能成功的保护样本。没有可恢复环境时只做从 reset 开始的配对运行，不伪称同状态反事实。
4. **新任务检索与执行。** 首轮可以用任务文本和工具契约检索；状态相关经验等观察到触发条件后才注入。不能读取未来步骤、测试标签或最终结果。预算有限时优先使用短卡片，检索开销计入 deadline。
5. **冻结测试。** 学习集产出经验、开发集选策略；测试前冻结卡片、阈值、检索与提示词。另设在线协议时严格先测当前任务、结算结果、再更新供后续任务使用，不能混报。

测试需要区分三个层次：原题再次执行、新实例但相同能力/模板、未见任务族或域。论文主张应依赖后两者；更换游戏 seed 或重复运行同一任务不能自动算跨任务迁移。

## 最小验证方案（尚未准入付费）

先在一个可本地 reset、有客观终态的多类型 benchmark 上做约 30 个任务的工程先导，例如文件、数据库、浏览器/API 各一组。遵守官方划分；若没有划分，按模板/资源/任务族分组并去重，再留开发和测试。小先导只判断信号是否可辨识，不能承担论文显著性结论。

比较同一模型/工具契约下四个版本：无记忆、等上下文预算的原始片段检索、ExpeL 风格规则、带触发/不适用条件的规则。先修好协议再比较任务经验，避免把序列化修复冒充迁移能力。追加消融：去掉条件、打乱记忆、只留成功步骤，识别收益到底来自提醒、答案重用还是条件筛选。

先测两个实际快慢配置的延迟分布，再锁定共同真实 deadline 和总费用；不预先承诺一定需要 5–10 分钟，也不按模型分别校准 deadline。每个 deadline 独立运行可感知时间的策略；同源任务按任务配对，报告逐域成功率、质量、错误复发、调用数、完整墙钟和总费用。检索/提炼/验证费用单列并计入摊销，成功轨迹独立报告延迟，防止快速失败拉低均值。

若“格式错误减少，但最终成功率不升且增加总时间”，只得出工程可靠性收益。若无条件规则同样有效，则不支持条件筛选机制。若只有原题重跑有效，则是记忆而非迁移。若改进仅来自放宽动作执行语义，则回到 harness 对照，不归因于经验学习。

## 同期工作如何约束创新

| 工作 / 已核实状态 | 已覆盖内容 | 对我们的约束 |
| --- | --- | --- |
| [ExpeL，AAAI 2024](https://ojs.aaai.org/index.php/AAAI/article/view/29936) | 从成功/失败提取规则，检索过往经验，无权重更新 | “错题本 + 反思 + 检索”不是新方法 |
| [MemRL，2026-01 预印本](https://arxiv.org/html/2601.03192v2) | 冻结模型，以记忆效用更新和两阶段检索进行学习 | 已有按经验价值选择；重复任务学习和留出迁移必须区分，不能泛称所有任务都迁移有效 |
| [Mem²Evolve，ACL 2026 主会](https://aclanthology.org/2026.acl-long.952/) | 经验蒸馏与能力扩展，联合记忆、工具等 | “经验 + 工具”及多域测试也已有；首版不需要复刻复杂能力生成系统 |
| [WikiSkill，2026-08 预印本](https://arxiv.org/html/2608.27454v1) | 轨迹→持续知识→可验证技能，包含候选验证和跨模型迁移 | “从 trace 编译技能、验证后接纳”也不是区别；其全部技能注入设置与检索适用性问题可进一步比较 |
| [EvoAgentBench，2026-07 预印本](https://arxiv.org/html/2607.05202v1) | 四领域能力迁移，528 train / 267 test，测试前冻结 | 与我们的目标最接近；其 test 能力有 train 支持，不等于未知能力迁移；AnchorSkill 使用测试能力标签，是诊断上界 |
| [Self-Evolving Harness，2026-09-29 预印本](https://arxiv.org/html/2609.38372v1) | 冻结同模型读完整记录、修改自身 harness，跨任务及域外评估 | 已覆盖泛化的自进化大方向；§5.7 明确缺少效果验证门槛且局部修复有副作用，低成本验收值得检验，但验证本身已有先行 |

这些是重合点和设计限制，不是“每篇都有缺陷所以我们的组合新颖”。尚未确认可投稿的新颖贡献；候选需要与这些工作的代码及实验协议直接比较。

## 中途发现、值得保留的方向

| 优先级与方向 | 已有证据 | 可证伪问题 / 最小验证 | 新颖性风险 |
| --- | --- | --- | --- |
| A：经验适用性与低成本验收 | 格式恢复不等于进展；一次局部规则可能损害别的任务；近作也报告副作用 | 用少量适用/反例/保护样本选择卡片，能否以更少验证费用保持留出质量？与全量验证、随机抽样、无验证比较 | WikiSkill 与 gated harness evolution 已接近；不能仅加 verifier 就声称新颖 |
| A：模型速度优势有多少来自协议匹配 | Flash/Pro 无调用占比不同，多调用未执行相差明显 | 同任务、共同 deadline、相同动作能力，原接口与严格单调用提示/原生工具接口分别比较排名；将协议处理开销计入 | harness 影响性能是已知问题；需回答具体混杂量与跨任务稳定性 |
| B：只学会“有效恢复”的经验筛选 | 多数错误段恢复调用，但立即加分较少 | 比较按消除报错、按子目标验收、按最终结果选经验；是否减少新任务重复错误并提高终态成功？ | 奖励稀疏与 credit assignment 已有大量研究；当前统计不是因果证据 |
| B：条件化短程序对快模型的收益边界 | 用户速度假设；当前两模型表现随任务变化 | 同一经验库在快慢模型上做有/无记忆配对，比较共同 deadline 下净收益；控制上下文和提炼成本 | ExpeL/WikiSkill/MemRL 已覆盖多部分，需证明增量机制而非简单组合 |
| C：长任务回退预防 | 本批仅 16/320 有扣分，单条可定位回退 | 在真正多分钟、可检查中间状态任务验证保护规则；先看回退是否常见 | 当前证据较弱，不宜马上当主线；重复文本不是跑偏标签 |

**推荐顺序：先完成协议基线与客观验收，再试“带适用条件的经验”是否有迁移收益；有信号才研究怎样节省验收成本。** 暂不同时做 router、自修改 harness、多 Agent 编排和模型后训练。
