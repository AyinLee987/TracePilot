# R3 编程开发先导与共同时间实验

日期：2026-10-06。当前为实现中的开发协议，尚无真实模型结果。完整目标仍包括共同 deadline、反馈机制与留出预测；首稿采样只是检查任务是否提供可研究的自然错误。

## 1. 先检查自然错误

首批固定 HumanEval+ v0.1.10 的任务 55、32、7、56，两模型 `deepseek-flash` / `deepseek-v4-pro`，每题每模型两次独立首稿，共 16 次生成。按 repeat、上述任务顺序、Flash/Pro 顺序串行执行；每次使用全新消息，不继承其他首稿或评分。API 不承诺可控采样 seed，不将两次回答当成确定性复现。

请求沿用已验证的 endpoint、价格与 usage 契约：非流式、thinking disabled、temperature=0.7、max_tokens=2048、n=1、无隐式或外层重试；HTTP 操作超时 60 秒、请求整体上限 65 秒。每请求保守预留若超过 0.20 元则在发送前拒绝，16 槽总保护上限 3.20 元；该子上限不是新付费额度，未来准入后仍需计入共享累计预算。未知用量、HTTP 或网络失败立即停止余槽并保留负债。候选只能看到题面、入口函数和公开反馈政策，不能访问宿主文件系统或隐藏数据。所有生成停止、在途请求清理且 HTTP 资源关闭后，才执行公开检查及离线隐藏评分；未知计费继续占用研究预算并单列，但不阻止对已经收到的候选进行离线评分。错误不触发额外模型调用。

代码解析规则固定为原始 Python 或唯一的 Python/无语言 fenced block，必须包含目标函数定义。完整文件原样使用；只有目标函数时，仅补题面中目标函数之前的公开 imports/helpers。正文说明、多段 fence、仅函数体、语法错误、非 stop 结束和工具调用均记为解析失败，不自动调用模型修复。完整 16 槽分母、未执行项及失败原因均保留。

若首批没有公开可定位的自然失败，按同样方案扩展预定开发题 16、99、18、31。仍无公开失败时停止扩大 HumanEval+，如实记录它不足以支持本轮反馈修复问题，另行冻结更合适的任务集；不通过编造错误来替代原生轨迹结果。隐藏失败不作为可见反馈，也不能用隐藏分数选择下一轮候选。

任务 43、25、156、145 暂时保留，不读取其内容来调提示或调规则。一个任务的所有首稿、续跑、共同状态和延迟变体属于同一划分。这只支持任务实例留出，不能称任务族泛化。

## 2. 评分和隔离边界

公开检查由题面示例与明确规格冻结；隐藏评分独立执行并只返回聚合结果。每次检查使用新输出目录及新容器。候选不获得期望值、宿主挂载、网络、凭证或 Docker socket；完整 Agent 未来接入时也不能获得研究仓库或隐藏结果目录的 shell 访问权限。

此实现是所选题的判定桥接，尚非完整 EvalPlus evaluator。公开与隐藏均使用 30 秒整批 worker 超时，不声称实现其逐输入规范化时间限制；只支持有限 JSON 返回类型。候选与 worker 同进程，不能声称抵抗恶意窥探或伪造。无隐藏结果参与在线停止、选择和提示构造。

任务 32 的参考代码在当前实现的固定多项式残差判定下为 881/888，必须单列数值判定限制。公开的不同合法根可以通过，不能用与参考根完全相等来评分。原输入用于父进程残差判定，候选原地修改参数不能修改 oracle；这一点与官方同进程输入变异行为分开披露。不得根据隐藏失败反复调整参考求解器或放宽容差。

## 3. 后续共同 deadline 机制实验

开发首稿实测后再冻结两个绝对秒数，所有模型与延迟条件共用。首版不向模型提示剩余时间。单调墙钟从任务就绪到提交，包含请求、解析、公开检查、选择、实际注入等待；截止后完成的候选不能替换已提交结果，清理时间另列。

比较两种闭环：独立生成加公开测试选择、读取上轮候选与公开诊断的反馈修复。两者使用相同选择规则：公开通过数最高，平分取最早完成者。首稿基线来自相同轨迹前缀。主指标是截止前实际选中候选的隐藏得分；逐轮隐藏得分仅用于运行后分析修复、退化和离线上界。

共同状态对照从开发阶段自然出现的公开失败中预先选定，保存不可变源码、任务和公开诊断，标注来源模型。尽可能平衡来源，无法平衡时如实报告。后续 R4 的特征、基线和留出预测规则必须在测试数据生成前冻结。

## 4. 当前执行门槛

多题判定与 16 槽采样器的零模型版本已通过审查；付费接缝、退出码分类及全部请求预留预检已实现，新增代码已通过实际 Claude Opus 5.5 初审与控制流增量复审，无本批代码执行阻断；提交后方可准备、激活并执行。离线 fake HTTP 只验证流程，不是模型能力结果。编程付费执行必须由同一个累计 200 元研究登记正式准入并继承 Timely 已知费用与未结负债；不得自行创建新额度。`extension-basis` 仍仅提供审计信息；实际准入使用 `prepare-coding16`、固定计划摘要与审查文件激活，本轮审查结束时尚未操作真实准入。真实共同 deadline 与反馈闭环尚未运行。

## 5. 已完成的零模型流程验证

固定 16 槽采样器的 6 项 fake HTTP 场景通过，包括 unknown、HTTP 失败、预算拒绝、取消后的预留保留、未准入付费拒绝及解析边界。实际 Docker 集成包含 8 个可解析候选和 8 个格式失败槽，22/22 容器清理、worker CLI 回收；公开检查严格在全部生成关闭后，隐藏评分严格在全部公开检查结束后。这些是合成候选/假模型结果，实际 API 调用和费用均为零，见 [验证记录](../../research/results/coding-pilot-validation.json)。实际 Claude Opus 5.5 增量审查对当前零模型功能无提交阻断；付费入口仍拒绝。退出码/容器提前消失分类和整批预留预检现已补齐；缓存命中、timeout 与 fail 分列。新增预算准入接缝单独审查与验证，历史检查不视为新增代码的完整认证。
