## Information, iteration and selection

Both loops share the same time-independent task/format prompt and native first-round message. They retain the existing endpoint, temperature 0.7, thinking disabled, one response, max_tokens 2048, no automatic retries, frozen parser and objective public checks. The old first-draft system prompt explicitly prohibits feedback and therefore cannot be reused unchanged; the new shared prompt is frozen with the plan before paid calls.

- Resample starts each request from the task and shared format instructions. It cannot see previous candidates, diagnostics or scores. Its controller still runs public checks and selects candidates.
- Repair additionally receives only the immediately preceding candidate and its available public diagnostic. There is no unbounded conversation accumulation. A parse failure is a separate event and can supply a fixed format diagnostic on the next scheduled repair iteration; it does not create an extra retry or a repaired candidate through local heuristics.
- A parsed candidate invokes the existing public checker in a fresh isolated container. After a successful return and confirmed tool cleanup, impose the condition's actual 0/1-second delay before the result becomes visible for selection or feedback. A parse failure invokes no tool and receives no artificial tool delay; retain this difference in the error taxonomy.
- Keep every candidate immutable. Select the candidate with the highest public passed count, with ties resolved by earliest availability. Public perfection does not stop the trajectory; subsequent equal-score candidates do not replace the earlier candidate. Keep the latest feedback state separate from the best selected state.
- Attempt 1 is the paired single-attempt baseline. If it is unparsed, unavailable or late, that baseline has no eligible generated candidate; do not relabel a later successful attempt as the first attempt. Separately report time to the first eligible candidate, which may require several attempts. In the common-state cohort, the historical fallback is not a new attempt. Hidden scores and reference solutions never enter messages, selection, stopping or routing features. All hidden scoring occurs after online requests/tools have closed.

Messages and diagnostic projection have explicit byte limits. If a dynamic request cannot satisfy the frozen input/fee guard, retain the stop reason and complete denominator; do not silently trim code or raise a cap mid-run. Guard-censored results are not interpreted as pure time constraints.

## Time and delivery semantics

Use one monotonic clock. Static dataset/image readiness and one complete study/source/ancestor audit may finish before `task_ready`; record this setup and keep it identical across conditions. Fresh candidate container startup remains online work. From `task_ready`, charge message construction, live admission checks, request preview and writing, HTTP, parsing, public execution, tool cleanup, injected waiting, candidate persistence and selection. Do not subtract overhead afterward.

This is a **common result-delivery deadline**, with bounded resource draining after the final deadline. It does not claim that a remote provider physically stops computing at that instant or that total compute is identical.

At each cutoff freeze the selected immutable candidate and its eligibility time. A candidate requires a complete public result, confirmed tool cleanup, the actual injected delay and persisted selection inputs before it is available; equality with the cutoff is late. A response arriving before a cutoff but judged afterward cannot enter that snapshot. Use `eligibility_time < cutoff` symmetrically: a delayed callback cannot admit a late candidate or discard an earlier eligible candidate. Record actual snapshot callback/persistence time and scheduling lag; never backdate delivery. Candidate availability by a cutoff and the controller's actual snapshot-delivery time are distinct measurements, so callback lag cannot be presented as an on-time physical delivery.

The short cutoff does not change model messages, candidate selection policy or subsequent dispatch behavior. Only the maximum cutoff ends the trajectory. The two online snapshots therefore estimate quality of a common prefix at different delivery cutoffs, not two independently terminated resource budgets. Snapshot bytes/hashes cannot later change. Deadline-boundary E2E also checks a single terminal cutoff; an independent paid short-cutoff sensitivity run is a separate future experiment, not implicitly claimed.

At the final cutoff stop new dispatch and freeze output. An already dispatched HTTP request may finish within its original bounded 65-second request limit, solely to settle usage and retain evidence. Late content cannot trigger parsing, another tool call, feedback or selection. Public checker work is likewise owned and bounded; any late result is ineligible. The event loop cannot synchronously run the checker. Do not discard a thread/process future and leave a container behind. Resource cleanup/drain must finish before the next trajectory; uncertainty stops the batch.

Record response arrival, parse completion, public start/return, delay release, eligibility, cutoff, snapshot persistence, late request, drain and cleanup separately. Report the physical trajectory's complete fees once. A short-cutoff cost attribution may include the full eventual bill of requests dispatched before that cutoff; label it as prefix attribution, not an independently observed short-run invoice. Real HTTP failures or missing usage still retain unknown liability and stop the remaining matrix.

## Numerical calibration and guards before paid execution

Old per-draft generation timers are not full-loop timers. The extension's whole generation phase was 89.401 seconds, compared with 22.743 seconds inside the sixteen local timers. Before choosing seconds, implement the online loop and measure its complete non-model overhead using fake HTTP and real public checks. Include the real lightweight admission path; do not validate the timer only with mocked disk reads. The full immutable history audit is outside `task_ready` and must still be audited and reported.

Use nearest-rank p90 (`sorted_values[ceil(0.90*n)-1]`) throughout this calibration. Pool all 32 prior HTTP request durations; include the format-failed response. Public-check time has 31 valid observations; do not impute zero for the unexecuted checker. On the new executor, run the eight development tasks with both policies once using fixed fake responses and real public checks. Keep two nonoverlapping overhead quantities: `setup_once` from task readiness to the first round's start (one-time trajectory creation/recording), and `round_other` covering the complete round except fake HTTP waiting, checker function wall time and separately recorded injected waiting. Request construction, admission checks, helper startup/IPC beyond checker time, persistence, selection, round-final records and gaps between rounds remain counted. Do not subtract the new helper's whole elapsed interval and then add only the old checker time; that would omit helper overhead. Include a real one-second delay check and a parse-failure path without a checker. Keep all calibration runs and source hashes.

Freeze, before new model calls:

`D_short = max(5, ceil(p90_existing_HTTP + p90_existing_public + 1 + p90_setup_once + p90_round_other))`

`D_long = 3 * D_short`

The `1` is the largest planned injected tool delay. The public-check function time includes its normal container cleanup; additional helper cleanup remains in `round_other`. A sum of marginal p90 values is a scale-selection rule, not the joint p90 of a full iteration or a guarantee that a future repair request fits. No per-model deadline or retrospective crossing-point selection is allowed. Any implementation issue revealed during calibration must be fixed and affected timing rerun before freezing the final plan.

Before paid execution, freeze the request-count guard as `max(64, ceil(D_long / min_existing_HTTP_duration) + 2)`, using all 32 requests including the parse failure. This is deliberately above the observed number of opportunities; the observed minimum is not a guaranteed future lower bound, so report guard hits by model/policy/delay and do not interpret them as pure deadline effects. The per-request conservative reservation cap remains CNY 0.20.

The calibration execution window is fixed at 3/6 seconds and is separate from the derived research deadlines. On the final frozen implementation, run one predeclared calibration containing all sixteen paths and two complete measured rounds per path. If any required round is incomplete or censored, do not emit an admissible calibration or rerun to select a faster passing sample. Preserve and report the failed measurements. Timing censoring alone is not an implementation defect and stops admission; it does not authorize a wider-window retry.
