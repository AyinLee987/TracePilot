### 候选探针研究什么

假设两个 Agent 此刻都还剩 15 秒，已经得到的答案证据完全相同，之前总共也都花了 20 秒。区别只在于：一个最近几次工具越来越慢，另一个最近几次越来越快。

**它们是否应该采取不同动作，取决于过去耗时是否真的能预测下一次，而不是取决于哪个 trace “看起来更紧迫”。** 我们想检验模型能否做出这种区分。

可证伪的问题是：

> 在相同语义证据和剩余时间下，LLM 能否利用历史工具耗时中的有效信息，并忽略无预测价值的耗时波动？错误发生在读懂 trace、估计下一次耗时，还是把估计转成行动？

这比“慢工具让 Agent 变差”更具体；后者可能完全由固定动作序列被 deadline 截断解释。时间历史有预测性也不是新发现，经典预测／调度算法必须作为强基线。

最新补检进一步收窄了空间：[Lookahead-R](https://arxiv.org/html/2609.35811v1) 已用执行历史预测工具延迟并做打乱成本的对照；[ChronosAttack](https://arxiv.org/abs/2609.27857) 已研究只改工具返回时机带来的决策变化。因此“用 trace 预测延迟”“延迟会改变决定”都不能单独作为创新。我们的待验证区别是固定证据及其顺序后，区分历史信息的预测价值、模型信念和动作，而不是再次证明延迟重要。

最小研究设计分两步：

1. **同一决策点的受控探针。** 固定证据、历史总耗时和当前 clock，只改变历史排列及其对未来的预测关系。比较当前 clock、原始时间 trace、由相同历史计算的统计摘要，以及无信息对照。让模型在继续取证、可选验证、立即作答之间选择。下一次真实延迟与正确答案均不能泄漏给策略。
2. **完整 Agent 验证。** 只将探针中值得解释的条件放入实际检索和可执行编程任务，验证是否影响截止前正确率，统计所有请求、工具等待与控制开销。局部探针不能替代端到端收益。

预测误差和行动误差应分别测量；询问预测本身会改变后续决策，因此放在独立配对分支中。若使用已知生成器的最优策略，只能称为受控环境的规范参考，不能假装现实环境拥有已知分布。

信息权限必须配平：原始 trace、摘要、外部预测器获得相同历史、过程说明和校准样本；一个额外训练过的预测器应单独标明。Oracle 概率只作额外信息诊断。不能要求不知道生成规律的模型达到知晓规律的 oracle，也不能根据实际抽中的下一次延迟事后给行动贴“正确”标签；应按当时信息下的期望效用评价。

首个受控探针明确披露相同的延迟规律，并固定、披露验证改善答案的概率，避免把质量收益信念误当成时间信念。随后再单独研究从往例学习规律的条件，不能混用两类结论。打乱延迟时在工具类型／参数类别内部操作，或显式控制工具身份与延迟的关联。

探针需要存在真实选择：已经有可提交候选，额外取证／验证可能提高质量但会占用时间。今晚 E1 的单一路径档案任务主要检查工具、时钟与账本，**并不检验候选 C；E1 阳性不能支持 C，阴性也不能否定 C。** 新假设仍需上述专门探针。

**值得继续的证据：** 无信息的慢反馈反复诱发错误提前作答；有效历史没有被利用；或同信息的简短统计摘要能纠正稳定偏差。需要排除措辞、长度、缓存、服务抖动和停止规则的解释。

**应停止扩大投入的情况：** 外部均值／分位数预测加答案预留规则已解释全部差异；任务只有唯一行动路径；效应只在特选 deadline 或人为制造的极端环境中出现。小样本没有显著差异只支持暂缓，不能证明不存在效应。

### Timely Machine 的缺陷能给我们什么

固定官方 commit `e13af2b` 后，已完成不调用模型的可复现代码检查：一般推理的计分容许 10% 超时，ML 容许 50%，游戏会先执行动作再检查 deadline；已审计的一般推理 reward 分支消费最后一次时钟读数，该路径未接收权威的完整答案完成时间。详见 [逐项证据和反方解释](timely-audit.md)。

**这证明的是公开实现的口径，不能证明论文表格受影响，更不能证明训练模型利用了漏洞。** 我们尚未复现 Timely-RL。相对预算、鼓励使用预算的奖励和噪声时钟也包含作者有意的设计选择，不能一概叫 bug。

这些发现用于确定自己的严格完成时间、在途结算和计分口径；单纯修正它们不足以构成论文主贡献。Timely 已包括 ML 编码和一般推理，不能再以“第一次扩展出文字游戏”为创新点。

### 备选与不建议扩张的方向

备选是**反馈返回时间与其有用性相关时，deadline 是否使控制器只看到一部分反馈，从而错误估计继续验证的收益**。这需要先证明真实任务中存在相应现象，再考虑按时间校准。它不是“首次考虑延迟反馈”：相关 bandit 理论已存在。

不单独推进“保留第一版／防越改越错”：VRR-Guard、AnytimeReasoner、BEACON 已有直接先行。也不同时启动 router 训练、真实购物、通用跨框架状态迁移和 Timely 式 SFT/RL。[反馈方向查重](feedback-priors.md)列出必要基线与否决条件。用户追加授权的 Pi／mini-SWE-agent 本地烟测是小型工程验证，单独记账但仍计入本项目同一总预算，不能视为候选 C 的实验结果。

### 明天读论文的顺序

二次查重后的统一顺序如下，先读前三篇即可做第一轮取舍：

1. [Timely Machine，ACL 2026 最终版](https://aclanthology.org/2026.acl-long.211.pdf)：§3–5 与计时／预算附录，作为核心出发点；若已读过可跳过。
2. [JAUNT](https://arxiv.org/html/2510.18550v1)：§5.2–5.3，确认“历史时延预测给 LLM 选工具”已经存在。
3. [Can LLMs Perceive Time?](https://arxiv.org/html/2604.00010v1)：§3 和附录 D.2，确认耗时预测与反馈校准已经测过，以及其前后任务不匹配的限制。
4. [Lookahead-R](https://arxiv.org/html/2609.35811v1)：§3.2、§4.4，检查历史、延迟预测与 Cost-Shuffled 的重合。

进一步做实证设计时，再看 [TicToc 最终版](https://aclanthology.org/2026.findings-acl.1848/)的时间干预与 Think–Answer mismatch、[Real-Time Deadlines v2](https://arxiv.org/html/2601.13206v2)的 urgency 对照，以及 [Calibration Is Not Control](https://arxiv.org/html/2606.21399v1)的同前缀预测／控制分解。不必明天一次读完；列入阅读清单不表示已复现其结果。
