# 研究方向可行性讨论：2026-10-05

本文件保留早期讨论时点。后续文献补检、真实先导与当前建议见 [最新研究决定](research/decision.md)，不要将下文当时“未运行实验”的状态当成当前状态。

供 2026-10-06 阅读论文与选择先导实验使用。本轮只讨论和查阅资料，没有运行模型能力实验，没有确定论文结论。项目仍处于 P1；下面的实验与策略均未实现。

本轮将“两个 idea”理解为：A，少量轨迹下的冷启动与跨任务迁移；B，根据 trace 判断模型升级是否值得。候选 C/D 是讨论中补充的方向。优先级是研究建议，不替代用户读论文后的选择。

## 1. 暂定判断

| 候选 | 一个具体问题 | 当前判断 |
| --- | --- | --- |
| A：少数据与迁移 router | 少量已执行轨迹能否支持新任务上的模型选择？ | 暂缓作为首月主线。轻量路由和状态特征已有工作，反事实标签与迁移评估比训练分类器更困难。 |
| B：模型升级的增量收益 | 同一个前缀，强模型接管比原模型反思多带来多少收益？ | 适合作为复现、诊断或对照；宽泛问题与已有论文直接重叠，需要具体新效应才可成为论文主张。 |
| C：工具时延分布下的模型选择 | 相同预设平均工具时延，不同波动/尾部风险是否改变限时表现与模型选择？ | 候选先导实证方向，最贴近 Timely Machine。新颖性与效果均未确认；先研究纯延迟，再考虑相关失败。 |
| D：反思的收益与开销 | 哪些状态值得额外反思，哪些状态直接恢复更好？ | 工程备选，最贴近现有项目；“出错后反思”或“按信号触发”本身不足以构成方法创新。 |

研究的目标不是预设“小模型胜出”或“trace router 一定有效”，而是找到可重复的效果、适用条件与代价。采用闭源模型时，只能比较具体部署与模型版本，不能据未知参数量解释差异。

## 2. 补检后必须调整的贡献表述

以下内容是阅读到的先行工作，不是本项目已经复现的结果。

- [Timely Machine](https://aclanthology.org/2026.acl-long.211/) 是时间约束的主要出发点，覆盖游戏、机器学习与一般推理。借鉴其工具延迟对照，不复现完整 SFT/RL 训练；不能声称首次拓展到游戏以外。
- [ProgRouter v2](https://arxiv.org/html/2608.25992v2) 已根据执行状态与进展逐步选模型。附录 D.3 的主结果来自在线学习稳定期，因此冷启动全过程值得核对，但不等于“冷启动路由尚无人研究”。
- [Agentic Routing](https://arxiv.org/abs/2607.11399) 的摘要已描述 harness 状态路由、执行数据闭环和 LightGBM 冷启动 ranker。本轮未完成其全文审计。
- [AgentCollab](https://arxiv.org/html/2603.26034v1) 已用自评进展触发强模型接管与回落，可作为低训练成本基线。采用简化版本时必须称为“复现近似”，不能混称原论文完整方法。
- [Calibration Is Not Control](https://arxiv.org/html/2606.21399v1) 已比较“失败风险”与“干预收益”，通过同前缀分支测量不同动作，使用前缀特征预测动作效用，并包含强模型干预与同模型修复分析。因此，B 的一般问题、配对分支和轻量控制器都不能单列为新贡献。其设定的固定/逐步成本与实际墙钟时间之间的差异，可以继续核查。
- [TACIT-Switch v2](https://arxiv.org/html/2608.27911v2) 已从累计轨迹证据学习成本感知的永久升级策略，在 ALFWorld 和 DABench 评估。训练使用从初态执行的 Cheap/Strong 轨迹与教师区间标注，未逐 checkpoint 穷举反事实。它的监督能否代表接手坏前缀后的可救性，是待验证问题；不是已证明缺陷。
- [The Handoff Tax](https://arxiv.org/html/2608.24358v1) 已系统研究模型升级/降级、切换时机与继承轨迹的接口。因此“模型切换存在额外代价”和“强模型接手可能受历史拖累”也不是新的宽泛命题。
- [When Tools Fail / ToolMaze](https://arxiv.org/html/2606.05806v1) 已系统设置工具故障与恢复评测；[REFLECT](https://arxiv.org/abs/2606.09071) 已研究干预支持的静默错误归因。不能把故障分类或重放验证本身写成首创。

补充工程先行工作：[vLLM SAAR](https://vllm-project.github.io/2026/06/02/session-aware-agentic-routing.html) 已考虑会话连续性、缓存相关切换开销和 trace。它是官方工程文章，不在这里当作同行评审论文。新检索到的 [Signed Rescue Routing](https://arxiv.org/abs/2609.07786) 摘要仍有实验数量和结果的 TBD 占位，本轮只视为相关主张，不采信为完成的实验证据。

## 3. 两个原始 idea 的可行性

### A：少量轨迹冷启动与迁移

能实现轻量策略，但普通日志没有“如果当时换模型会怎样”的标签。迁移也必须明确是换任务模板、领域、工具还是模型池；首月同时覆盖这些轴不可取。

如果以后推进，先固定模型对、工具和任务域，只留出任务模板。比较同升级率随机选择、任务文本、步骤类型、失败次数规则与完整 trace；所有分支按原始任务分组划分，不能随机拆步骤。训练量学习曲线要同时报告采样费用，不只报告训练时间。

**停止理由可以是预算下证据不足。** 置信区间包含零不证明没有收益；若有限数据无法支持进一步投入，应记录不确定性，而非发布“trace 无效”的结论。

### B：预测升级收益

不能预设“工具错就不升级、推理错就升级”。更强模型可能规划出更少的工具调用，也可能改道成功；原模型的一次反思有时已经够用。HTTP 错误码规则必须作为对照，不能把识别注入标签当研究成果。

最小诊断可在预先定义的决策边界保存状态，再分别执行：原模型继续、原模型使用固定反思模板、强模型使用同一模板继续、规则恢复后原模型继续。②与③拥有相同可用信息和反思要求；接管持续时间与后续策略要在实验前固定。加入正常状态，报告误升级。

该分支协议用于复现和诊断，不能声称首次提出。事后根据所有分支结果挑最佳动作，只是离线机会空间估计；单次抽样会抬高这个估计，需要重复和不确定性报告，不能把它当可部署策略。

一个更窄的备选问题是：TACIT 类“强模型从头成功”的廉价监督，在什么状态下错误估计中途接管收益？少量真实分支能否校正这种偏差？这也需进一步查重，且不应把成本口径与策略差异混为一谈。

## 4. 候选 C：工具时延分布与时间约束

**待验证问题：** 在相同预设平均工具时延下，只改变波动和尾部形态，是否会改变两个模型在相同绝对截止时间下的相对表现？均值条件下选出的模型，在另一种时延分布中会损失多少？

首轮固定一个 Agent、两种模型、只读工具与固定语料。先只比较低方差与长尾两种延迟条件，工具语义和正确性保持不变；突发相关性、故障、第二任务域分阶段加入，不展开全部组合。

第二轮讨论后增加一个关键因素：**时间信息不可见 / 每轮显式提供剩余时间**。同一条件下两模型接收相同时间反馈规则；反馈自身的 token 和执行开销计入。最小因子是模型 × 延迟形态 × 时间可见性，首轮只用一个在开发集确定的绝对 deadline。

必须区分“延迟把既有流程拖慢”和“Agent 看到时间压力后改变行动”。没有时间反馈、没有影响行为的超时/重试，且工具语义与模型服务不受等待影响时，可以用未受时间约束的轨迹离线施加延迟，构造**固定行为的参考预测**。这一参考需要少量在线检查其假设，不能宣称在真实 API 上总是精确。主实验在时间可见条件下真实执行；比较实际调用次数、证据覆盖与限时正确率相对于参考预测的变化。

一个可预先定义的交互是：长尾相对低方差的限时成功率变化，在时间可见和不可见条件之间是否不同，再比较两个模型。提示词差异、模型自身时延和服务抖动仍是需要控制的解释，不把一个残差自动称为因果效应。时间反馈还可能改变提示缓存命中率，应固定插入位置并记录缓存用量；是否增加等长度无信息反馈对照，在先导前决定。

一个 deadline 只支持该时间点的结论。正式评估前选定一个主要对比，例如时间可见条件内的“模型 × 延迟形态”差异；三因素交互作为探索分析，不用小样本追逐显著性。在固定行为假设经检查的不可见条件下，可离线扫描多个 deadline 作敏感性诊断，但不能据此事后选择主结果的截止点。

必要控制：

- 使用预先生成、可复现的外生延迟过程，同一任务/随机种子跨模型配对。策略不能看到未来延迟或注入标签。
- 匹配的是环境的预设均值与服务机制，不保证各模型实际遇到的平均延迟相同：它们选择的工具和调用次数可能不同。报告实际暴露分布与调用量，不按结果事后重采样来强制对齐。
- 后续若研究相关性，可比较相同延迟集合的独立打散与成簇排列，同时核对外生调度与调用规则。它仍是受控仿真，不能冒充生产故障分布。
- 使用真实经过的墙钟时间执行 deadline 和取消；提前冻结时钟反馈方式。仅给现有轨迹事后加延迟可作为成本诊断，不能冒充时间会改变动作与终止的在线主实验。
- 工具本身实际运行时间与注入等待分别记录。新查询在固定语料上执行，不直接播放另一条轨迹的响应。
- 在相同绝对截止时间下比较；按小批次交错运行模型与条件，固定并发/限流，记录 Provider 时延及缓存情况，避免时段负载造成排名变化。
- 截止时间和任务集在开发集确定，完整留出测试集验证。不得根据模型结果剔除任务；工具依赖任务、自然失败或困难题只能作为预先声明的诊断分层。

首要指标是 deadline 内的任务成功率/客观质量，同时报告总费用、实际模型与工具耗时、交互次数及超时比例。截止条件的观察时长被封顶，不能把其 p95 当成未截断完成时间的 p95，也不能仅对成功样本取分位数而隐去失败。不能通过早停失败来获取漂亮的延迟。先导样本不足以稳定估计尾部分位数，也不能用多个 checkpoint 充当独立任务。

另报告正常终止时的质量、证据支持和提前作答情况。若要宣称“维持质量且更高效”，预先设质量非劣边界并检查区间；若证据不足，仍可报告质量/时间/费用的原始权衡，但不能宣称保持质量。不能把不受 deadline 限制的质量误当成同一个优化目标。

用于固定行为参考的“不设研究 deadline”运行是独立诊断组，仍有显式步数/费用安全上限，达到上限的运行标为截断。该组的真实费用全部计入预算，既不免费复用时间可见条件，也不把截断运行当成自然完成样本。

需要看见的信号是“模型/策略 × 延迟条件”的可重复交互，或有机制解释的选择损失；仅发现长尾会使任务更慢不足以支撑贡献。排名反转只是可能结果，不是必须调出来的目标。只有一个模型对时，结论限制在该模型对与部署。

进入正式实验前，需要确认三点：相关论文未覆盖拟主张的具体效应；所选任务确实有足够工具交互；时间反馈引起的行为变化值得在现有预算下继续验证。先导未观察到差异只能支持“暂不投入”，不能证明效应不存在。B 的时间分解可复用作诊断，但首轮 C 不引入动态模型切换，以免额外增加环境快照与接管接口因素。

## 5. 候选 D：固定模型的反思开销

比较没有额外反思、每步反思、显式错误规则触发、trace 触发；先固定模型和恢复提示，区分反思、重试与检索改写。评价增量成功率与全部开销，而不以反思文本是否“看起来合理”评分。

该方向最容易复用用户项目，但新颖性风险高。[The Cost of Dynamic Reasoning](https://arxiv.org/abs/2506.04301) 已分析反思深度等开销，[Thinking vs. Doing](https://arxiv.org/abs/2506.07976) 已研究交互扩展。因此目前将其保留为工程备选，不预先承诺论文方法贡献。

## 6. 工程与预算边界

目前已有运行、主模型、工具、检索等 Langfuse 观测，以及合成数据的真实集成验证。尚无真实模型能力基线；本地 JSONL/决策前缀、Provider attempt 与辅助调用细账、实验可重放状态仍待补齐。现有暂停续跑验证不等于实验所需的完整环境快照。

只为选中的先导实验补必要能力。A/B 需要状态恢复；C 第一轮可独立端到端执行，不应被通用 checkpoint 框架阻塞。复用只读检索和固定语料，首月不做真实购物、通用多框架迁移或训练基础模型。

C 的最小计时前提仍需落实：关闭 Provider SDK 隐藏重试，或逐次记录其次数、耗时和用量；工具计时包含并明确标注内部 embedding 等调用，无法拆分的部分保持未知。注入等待单独计时，不把未观测的辅助调用变化解释成行为效应。先导还要统计批次墙钟时间与并发限制，不能把真实等待当成无时间成本。

预算是待采用的建议，不是已发生费用或已启动的付费实验：先导最多约 200 元，正式样本约 1,000 元，复跑/第二模型对约 500 元，异常预留约 300 元。实际规模在少量调用测出费用后确定；先导费用过高则缩小范围或停止，不自行突破总额。

上述是**选定一条研究主线后的共享总额**，不是每个方向各有 2,000 元，也不是在原 P2–P4 排期外新增一笔。若选择 C，路由和跨领域实验按剩余预算延期或缩小；最终分配与周计划一并确定。

实验账本直接汇总前缀生成、所有续跑分支、完整基线、路由/自评、评分、重试的真实费用。部署某条策略的单任务费用与为了选择策略产生的研究总账分开报告，不能给已经是续跑费用的项目再乘一次“续跑比例”。未知费用标为未知，不能记零。

小先导只用于检查可评分性、失败机制、费用和效果量，不作显著性结论。正式样本量根据可接受差异与先导变异估计；成功率是质量护栏，不能因为时间指标更容易显著就省略。重复、区间和任务级聚类应与设计匹配。

## 8. 讨论记录与证据范围

Codex 负责检索与工程核对；Claude CLI 使用提供的论文事实摘要进行批评，没有自行浏览。完成两轮讨论，CLI 均报告 `claude-opus-5-5`。第一轮建议先做升级收益实证；补检发现更直接先行工作后，Claude 撤回其宽泛新颖性主张，优先考虑 C 的窄实证，D 为工程备选。完整的私有 CLI 输出留在 Git 忽略目录，只提交脱敏结论。

Codex 采纳了第二轮关于固定行为参考预测、避免首轮引入模型切换的意见；Claude 接受了关于选择偏差、非显著性解释、成本重复折扣与环境恢复的纠正。未采纳“长尾必然造成排名反转”或“离线计算在 API 场景总是精确”的绝对说法；它们需要额外假设。也未把 C 必须依赖的基础设施扩大为通用快照系统。文档检查记录见 [本次审查记录](reviews/2026-10-05-research-directions.md)。

这是可行性讨论，不是论文复现或学术新颖性认证。最终研究问题、数据集、模型版本和正式预算应在先导前确定。
